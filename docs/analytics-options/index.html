Analytics · four dashboard designs

A light, first-party analytics screen for the admin console: who is on the shop right now, what they are reading, where they came from, what they searched for and what they bought. Pick a letter; nothing on the shop or the admin has changed.

Sample data Preview animation Every number on this page is invented for a UAE K-beauty shop. The live parts tick every few seconds in the preview only, so you can feel them.

What the shop records today, and what a light tracker would add
  1. Product views only: POST /api/viewed (session + CSRF, 60/min throttle) feeds a kbb_viewed cookie, and product_view_days keeps one counter per product per day for 90 days ("Most viewed"). Nothing records categories, blog posts, the homepage, referrers or devices.
  2. On-site search: search_terms keeps term · day · hits · results, so the keyword list exists already, zero-result searches included.
  3. Orders are in the database (revenue, items), but no source or UTM campaign is stored against an order. GA4, Meta and TikTok tags (App\Services\Analytics) send data out to those services and bring nothing back. SearchConsoleSource can already fetch Google keywords once it is connected.
  4. Needed: one cookie-less beacon per opened page (navigator.sendBeacon, inline, after load) carrying path, referrer host, UTM tags, language and a coarse device class. It goes to a new stateless endpoint rather than /api/viewed, which is product-only and session-bound. Country and city come from a CDN header or a local GeoIP lookup.
  5. Stored as: per-minute counters (page × source × device × country) rolled into daily rows, plus a 5-minute "active" table keyed by a daily-salted hash in place of a cookie. Add-to-cart, checkout and order events reuse the same beacon, and an order stamps its first-touch source.

                                                              How it stays light
                                                              • One tiny beacon, no cookies, no extra script file. A few lines inline at the end of the page send one navigator.sendBeacon after the page has loaded, so it never delays what the shopper sees. There is no consent banner to add and nothing extra in the <head>.
                                                              • Counted per minute, not stored per visit. Each beacon adds 1 to a counter row for that minute (page, source, device, country). There is no row per visitor and no raw log to grow forever; minutes roll up into days.
                                                              • The dashboard reads summary tables only. Opening Analytics never scans visits. Today, 7 days and 30 days are a few hundred summary rows at most, so the screen costs the same with 100 visitors or 100,000.
                                                              • Live polls every 15 seconds, only while you are looking. The live panel asks once every 15 s while the tab is visible and the screen is open. It stops when you switch tab, lock the phone or leave the screen.
                                                              Rough cost: 1 small write per page view, batched, so a busy minute of 300 page views becomes a handful of counter updates. Each live refresh is one indexed read of the last 5 minutes. The shopper downloads no new file; the beacon is about 300 bytes of inline script.
