# Lane GC — bulk document shots

Four orders, one batch of each document. Written by
`tests/Feature/BulkDocumentPreviewsTest.php` on every suite run, so what is here
is what the route serves rather than what somebody exported once.

| File | What to look at |
|---|---|
| `bulk-packing-slips.*` | Four picking sheets, no prices anywhere, one per page. Carries **no invoice reference** — printing a picking list does not issue an invoice number, and the preview order proves it. |
| `bulk-dispatch-labels.*` | Four A6 labels. The second is cash on delivery and carries the **COLLECT AED 234.50** box; the others do not. No product name, brand or SKU on any of them — a label is on the outside of the parcel. |
| `bulk-delivery-notes.*` | Four handover sheets with signature blocks. |
| `bulk-invoices.*` | Four invoices, each with its own number, issued by this run. The fourth order was placed in Arabic and its sheet is `lang="ar"` inside an otherwise English page. |

`.html` is the document the route returns. `.pdf` is that file printed through
Chromium's own print pipeline — the same path the owner's Print → Save as PDF
takes — and is the evidence for the page geometry:

| Document | Pages | Page size |
|---|---|---|
| bulk-invoices | 4 | 594.96 × 841.92 pt (A4) |
| bulk-packing-slips | 4 | 594.96 × 841.92 pt (A4) |
| bulk-delivery-notes | 4 | 594.96 × 841.92 pt (A4) |
| bulk-dispatch-labels | 4 | 298.08 × 420 pt (A6) |

Four orders, four pages, one order per page, no trailing blank. `.png` is the
on-screen view, where the `.no-print` sheet counter is visible and the printed
sheets are not yet separated.

The PDFs and PNGs are **not** regenerated by the suite — they come from
Chromium and are not byte-reproducible. Only the `.html` files are. See
`docs/GC-BULK-PRINTING.md` for the negative control that shows the page-break
rule is doing the work.
