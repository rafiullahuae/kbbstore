# Marketing Pixels — research note (Lane MP, 9 October 2026)

What can be one click, what cannot, and why. Every claim has its source.

**How this was researched.** The attached plugin (Meta pixel for WordPress, `official-facebook-pixel` 5.2.2) was unzipped into `storage/mp-ref/` and read, never run. Web research used search. Direct page fetches to `developers.facebook.com`, `developers.google.com` and `business-api.tiktok.com` were refused by this sandbox's network, so official pages are cited from search results that quote them. Where only a third-party source was found, it says so. Where something could not be confirmed, it says that too.

## 1. How the Facebook plugin's "auto connect" works

Read from the plugin source (`core/class-facebookwordpresssettingspage.php`, `core/class-facebookpluginconfig.php`, `js/settings_page.js`, `js/fbe_allinone.js`, `core/class-facebookwordpresssettingsrecorder.php`):

- The plugin opens Meta Business Extension (FBE) in a popup or iframe at `https://business.facebook.com/fbe-iframe-get-started/?…`, under Meta's own app id `221646389321681`. Plugin 5.2.2 also has a "Facebook Login for Business" iframe at `/fbl4b-iframe-get-started/?app_id=…&config_id=1509863200530691`.
- It sends `extras` with `setup.external_business_id` (`fbe_wordpress_<random>`), the currency, the time zone and `business_vertical: ECOMMERCE`. The scopes are `manage_business_extension,business_management,ads_management`. The redirect is `https://business.facebook.com/fbe-iframe-handler`.
- The popup returns the pixel id and an access token to the page by `postMessage`. The page checks the origin (`https://business.facebook.com` / `www.facebook.com`) and posts them to `admin-ajax.php?action=save_fbe_settings` with a nonce. The saved fields are `pixelId`, `accessToken` and `externalBusinessId`.
- Conversions API: a server event per browser event, with a shared random UUID event id (`EventIdGenerator::guidv4()`). It sends hashed advanced-matching fields and has a half-open circuit breaker that pauses CAPI after an authorisation error. It pins Graph API `v25.0` (`GRAPH_API_VERSION`).

## 2. Can this shop do the same? No, and here is why

| Platform | Official one-click | Usable by this shop? | Source |
|---|---|---|---|
| Meta | Meta Business Extension (FBE) | **No.** The partner app needs the *private* `manage_business_extension` permission. A Meta representative must add the app to an allow list. The app must also be owned by a verified business and pass App Review (Advanced Access to ads_management and more). The plugin works only because it uses **Meta's own** app id. Borrowing that id, or WooCommerce's, would be impersonation. | [Meta: Pixel and Conversions API onboarding (FBE)](https://developers.facebook.com/docs/facebook-business-extension/fbe/get-started/pixel-capi-onboarding/) |
| Meta | Login for Business with a *system-user* config (the CAPI integration template) | **Not for a self-hosted shop.** It is the Tech-Provider flow: the code is exchanged for a business-integration system-user token for a *client* business. | [Meta: Facebook Login for Business](https://developers.facebook.com/documentation/facebook-login/facebook-login-for-business), [CAPI integration template](https://developers.facebook.com/documentation/facebook-login/facebook-login-for-business/conversions-api-integration-template/) |
| Meta | Login with the owner's **own** app | **Yes.** An app that manages only its owner's ad accounts needs only standard (since 4 May 2026, "Limited") access to ads_read and ads_management. No App Review is needed. | [Meta: Marketing API authorization](https://developers.facebook.com/docs/marketing-api/get-started/authorization), [Meta blog: access tier renamed](https://developers.meta.com/blog/updates-to-ads-management-standard-access-feature/) |
| Google | Merchant API / Content API with OAuth | **Not worth it.** The Content API for Shopping reached sunset on 18 August 2026: it fails intermittently with 410 from 1 September 2026 and shuts down fully in early 2027. The Merchant API needs a Google Cloud project registered to the Merchant Center account. An OAuth client in "Testing" status gets refresh tokens that expire after 7 days. Merchants who submit by **file URL** are not affected by the migration. | [Google: Content API deprecation and sunset](https://developers.google.com/shopping-content/guides/deprecation-and-sunset), [Google dev page on Testing-mode tokens (7 days)](https://developers.google.com/health/setup), [Feedonomics on file feeds](https://feedonomics.com/blog/google-merchant-api-migration/) |
| TikTok | Platform partner integrations (Shopify, WooCommerce…) | **No public self-serve OAuth for a single shop was found.** The Events API token is generated by hand in Events Manager. | [TikTok Events API 2.0](https://business-api.tiktok.com/portal/docs/events-api-2.0/v1.3) |

**What was built instead (the closest honest equivalent):**

1. A guided wizard per platform. Each numbered step has a deep link, says what to copy, and has a box to paste it into.
2. **Automatic verification by the platform itself**:
   - Meta: `GET /{pixel}` with the token, plus a real Test Event read back as `events_received`.
   - GA4: Google's validation server checks the purchase body, then a `debug_mode` event is sent for DebugView.
   - TikTok: a test event read back as `code: 0`.
   - Live page: the home page is fetched and each loader and verification tag is looked for.
   - Feeds: every item is parsed and checked.
3. An optional real **"Connect with Facebook"** with the owner's own Meta app. The Instagram one is reused when present. It lists his pixels so he can pick one. The CAPI token stays a paste, because the user token from that login expires and Events Manager's generated token does not.

## 3. Facts used, per platform

### Meta
- CAPI is `POST /{pixel-or-dataset-id}/events` with `access_token`, and `data[]` holds `event_name`, `event_time`, `event_id`, `action_source: "website"`, `event_source_url`, `user_data` (hashed `em`/`ph`…, plus raw `client_ip_address`, `client_user_agent`, `fbp`, `fbc`) and `custom_data`. ([Meta: Using the API](https://developers.facebook.com/docs/marketing-api/conversions-api/using-the-api/), [Freshpaint reference](https://documentation.freshpaint.io/integrations/destinations/direct-response-ads/facebook-conversions-api/facebook-conversions-api-reference))
- **Graph version:** Meta's pages show both v25.0 and v26.0. v25.0 shipped 18 February 2026, and the official plugin 5.2.2 pins v25.0, so that is what `PlatformClient::GRAPH_VERSION` uses. ([adsuploader summary](https://adsuploader.com/blog/meta-conversions-api); the plugin source.) *Unconfirmed: whether v26 is GA.*
- **Dedup:** browser `eventID` = server `event_id`, plus the same event name, within 48 hours of the first. Meta does not deduplicate server-only pairs, and an order number is a good natural id. ([Meta: Handling duplicate events](https://developers.facebook.com/docs/marketing-api/conversions-api/deduplicate-pixel-and-server-events))
- **Token:** Events Manager → dataset → Settings → Conversions API → *Set up manually* → *Generate access token*. Meta does not store it, so copy it at once. ([Meta: Dataset Quality API](https://developers.facebook.com/docs/marketing-api/conversions-api/dataset-quality-api/), [Datahash guide](https://www.datahash.com/docs/meta-web-conversions-api))
- **Event Match Quality** scores website CAPI events, and more customer parameters raise it. ([Meta: Dataset Quality API](https://developers.facebook.com/docs/marketing-api/conversions-api/dataset-quality-api/), [CustomerLabs](https://www.customerlabs.com/playbook/meta-conversions-api-setup/))
- **Normalisation:** email trimmed and lowercased; phone as digits with the country code and no "+"; names lowercased; country as a 2-letter lowercase code; all SHA-256. ([Meta: customer information parameters](https://developers.facebook.com/docs/marketing-api/conversions-api/parameters/customer-information-parameters); the page could not be fetched here, so the rules are as the plugin's `AAMFieldsExtractor` applies them)
- **Domain verification:** Business Settings → Brand safety → Domains → meta-tag `facebook-domain-verification`. Keep it in place. ([IONOS guide](https://www.ionos.com/digitalguide/domains/domain-tips/facebook-domain-verification.md); third-party)
- **Catalog feed:** Commerce Manager takes a scheduled data feed in RSS/Atom XML with the Google `g:` namespace, and the ids must match the pixel's `content_ids`. ([PixelYourSite docs](https://www.pixelyoursite.com/docs/facebook-product-catalog-feed); third-party)

### Google
- **GA4 Measurement Protocol:** `POST /mp/collect?measurement_id&api_secret` with `client_id` and `events[]`. `/debug/mp/collect` validates and returns `validationMessages`, but **does not check the api_secret or measurement id**, so the last step of the check is DebugView. ([Google: Validate events](https://developers.google.com/analytics/devguides/collection/protocol/ga4/validating-events), [Endframe](https://www.endframe.io/blog/ga4-measurement-protocol-server-side-conversions))
- **GA4 purchase dedup** works on `transaction_id`, for the **same user only**, on web streams. So a server purchase is sent only with the shopper's own `_ga` client id; with none it is skipped. ([Google: Measure ecommerce](https://support.google.com/analytics/answer/12313109))
- **Ads enhanced conversions:** `gtag('set','user_data',{sha256_email_address, sha256_phone_number})`. Normalise first: trim, lowercase, E.164 phone, and drop the dots in gmail local parts. ([Google Ads help 9888145](https://support.google.com/google-ads/answer/9888145))
- **Consent Mode v2:** four signals (`ad_storage`, `analytics_storage`, `ad_user_data`, `ad_personalization`). The default goes before any config, may be scoped by `region`, and is required for EEA/UK ads measurement. ([CookieChimp guide](https://cookiechimp.com/blog/google-consent-mode-v2-implementation-guide); third-party)
- **UAE:** the PDPL (Federal Decree-Law 45/2021) does not name cookies. Vendor guidance treats consent as the safe basis, and the status of the executive regulations is reported inconsistently. So the shop ships with consent mode **off** and offers "EEA" denied-by-default. ([Simmons & Simmons FAQ](https://www.simmons-simmons.com/en/publications/ckwugz8lu16rs0a44qvbqcbz9/uae-personal-data-protection-law-faqs), [CookieYes](https://www.cookieyes.com/blog/uae-data-protection-law-pdpl/)) *Not legal advice.*
- **Merchant Center feed:** the required attributes are id, title, description, link, image_link, availability, price, condition, plus brand and gtin/mpn or identifier_exists. Images must be at least 100×100 now and at least **500×500 from 31 January 2027**, with 1500×1500 recommended. ([Google: 2026 spec update](https://support.google.com/merchants/answer/16989427), [PPC Land](https://ppc.land/google-blocks-product-images-under-500-x-500-pixels-from-31-january-2027/)) The feed (Lane SEO's) already uses the original upload, which is the largest copy. The shop's image variants are downsized WebP tiles, smaller than the original, so the original is the right one.
- **Site verification:** Merchant Center → Business info → Website → HTML tag, then Verify, then Claim. Keep the tag. ([Google Merchant help 12159158](https://support.google.com/merchants/answer/12159158))

### TikTok
- **Events API 2.0:** `POST https://business-api.tiktok.com/open_api/v1.3/event/track/` with header `Access-Token`, and body `{event_source: "web", event_source_id: <pixel>, data: [{event, event_time, event_id, user, page, properties}]}`. The 1.0 `/pixel/track/` endpoint is sunset. ([TikTok: Events API 2.0](https://business-api.tiktok.com/portal/docs/events-api-2.0/v1.3), [Tealium connector](https://docs.tealium.com/server-side-connectors/tiktok-events-connector/))
- **Events:** ViewContent, AddToCart, InitiateCheckout and CompletePayment (purchase). Some platforms also list "Purchase", but Shopify and PrestaShop integrations use CompletePayment. ([TikTok: supported events, Shopify](https://ads.tiktok.com/help/article/supported-events-shopify?lang=en))
- **Dedup:** the same `event_id` and the same event name on pixel and server. A 48-hour window is reported. ([TAGGRS](https://taggrs.io/docs/server-side-tracking/tiktok/event-deduplication), [Adobe](https://experienceleague.adobe.com/en/docs/experience-platform/tags/extensions/server/tiktok/overview))
- **Hashing:** email and phone are SHA-256 of the trimmed, lowercased value. ([Benly](https://benly.ai/learn/tiktok-ads/tiktok-ads-events-api-setup); third-party) *Unconfirmed from TikTok's own page: the exact `test_event_code` field name. It is used as a top-level body field, as TikTok's GTM template does.*
- **Catalog:** Data Feed Schedule accepts CSV, XML (RSS/Atom), TSV and GZIP over HTTPS, hourly or daily. A catalog goes stale after 7 days without an update. ([TikTok: Create and manage catalogs](https://ads.tiktok.com/help/article/create-manage-catalogs?lang=en), [WisePIM](https://wisepim.com/guides/product-feed-optimization/tiktok-catalog))

## 4. Decisions that follow

- **One feed builder, three addresses.** Google keeps SKU ids (`/feeds/google-merchant.xml`). Meta and TikTok get `/feeds/meta-catalog.xml` and `/feeds/tiktok-catalog.xml`, whose ids are the product ids the pixels send (variants: `<product>-<variant>`, with item_group_id = the product id). Catalog ads need the ids to match.
- **Server events are sent after the response** (`app()->terminating`, because this host runs no queue). They have a 2 s connect / 4 s total timeout and a ten-minute per-platform breaker on token refusal, the plugin's own design.
- **No server ViewContent or PageView.** A prefetch renders the page on the server, so a server event per render would count prefetches.
